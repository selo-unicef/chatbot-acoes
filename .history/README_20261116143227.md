# Chatbot NUCA – versão Groq

Projeto Flask + HTML/CSS/JS para consultar ações dos NUCAs do Selo UNICEF. **A geração de respostas usa somente a API da Groq**, com streaming no navegador, contexto de conversa, busca em dados locais/CDN e estatísticas calculadas sem chamadas ao modelo.

Esta versão substitui os adaptadores OpenAI/Gemini para geração de texto pelo SDK oficial `groq`, usando por padrão o modelo de baixo custo `openai/gpt-oss-20b`. **O prefixo `openai/` no nome do modelo é apenas o identificador definido pela Groq: NÃO é necessária uma chave OpenAI para gerar respostas.**

> O projeto anterior não continha dados reais das ações nem credenciais de produção. Você deve configurar uma fonte de dados antes de obter respostas sobre registros específicos. Os exemplos e testes não são dados reais.

## 1. Configuração local

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Crie a chave em <https://console.groq.com/keys> e edite `.env`:

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=gsk_SUA_CHAVE_AQUI
GROQ_MODEL=openai/gpt-oss-20b
GROQ_REASONING_EFFORT=low
MAX_OUTPUT_TOKENS=1200

# Use pelo menos uma fonte de dados: snapshot/CDN OU vector store legado.
SNAPSHOT_URL=https://seu-dominio.example/data/actions.json
```

Depois execute `python app.py` e abra <http://localhost:5000>. A aplicação tem as rotas `/`, `/health`, `/api/chat` (JSON) e `/api/chat/stream` (SSE). O site continua usando `/api/chat/stream`, que exibe a resposta progressivamente.

Se você quiser um teste imediato **sem CDN**, aponte `SNAPSHOT_PATH` para um JSON local exportado, seguindo o formato abaixo. Use `SNAPSHOT_PATH=/caminho/absoluto/para/actions.json` e deixe `SNAPSHOT_URL` vazio.

## 2. Heroku (após enviar o repositório)

Em **Heroku → Settings → Config Vars**, remova ou deixe sem efeito as configurações antigas `OPENAI_MODEL`, `GEMINI_MODEL` e `GEMINI_API_KEY`. Configure:

```bash
heroku config:set AI_PROVIDER=groq \
  GROQ_API_KEY='gsk_SUA_CHAVE_AQUI' \
  GROQ_MODEL='openai/gpt-oss-20b' \
  GROQ_REASONING_EFFORT='low' \
  MAX_OUTPUT_TOKENS='1200' \
  --app NOME-DO-APP

heroku config:set SNAPSHOT_URL='https://seu-dominio.example/data/actions.json' --app NOME-DO-APP
```

Não inclua chaves em commits ou arquivos servidos pelo navegador. O `Procfile` existente inicia Gunicorn. A rota `/health` confirma **somente** que existe uma chave Groq e uma fonte configurada: não testa conectividade real, saldo, modelo nem qualidade dos dados.

**Importante:** a troca do provedor de IA não converte automaticamente o antigo vector store OpenAI em um banco Groq. A Groq gera as respostas; as evidências devem continuar vindo do snapshot ou de uma busca externa.

## 3. Fonte de dados e economia

### Recomendado: snapshot público via CDN

Mantenha a view de ações públicas aprovadas do Supabase e publique um arquivo JSON por GitHub Actions, Heroku Scheduler ou outro job a cada 1–2 horas. O chatbot baixa o JSON, mantém cache no servidor e faz buscas e estatísticas localmente. **Nesse modo, não é preciso `OPENAI_API_KEY` nem `OPENAI_VECTOR_STORE_ID`.**

```dotenv
SNAPSHOT_URL=https://SEU-USUARIO.github.io/SEU-REPO/data/actions.json
SNAPSHOT_TTL_SECONDS=7200
RETRIEVAL_MODE=auto
OPENAI_API_KEY=
OPENAI_VECTOR_STORE_ID=
```

Formato esperado do JSON:

```json
{
  "actions": [
    {
      "id": "42",
      "titulo": "Mutirão cultural",
      "descricao": "Oficinas e atividades com adolescentes",
      "municipio": "Exemplo",
      "uf": "AL",
      "ano": 2026,
      "tema": "Cultura",
      "pessoas_mobilizadas": 80,
      "status": "Aprovado",
      "url": null
    }
  ]
}
```

Não publique nomes, CPFs, telefones, e-mails ou outros dados pessoais de adolescentes. A view `vw_nuca_chat_public` deve conter somente os campos aprovados para publicação, inclusive revisando o conteúdo de `descricao`. O script `scripts/export_snapshot.py` e o workflow `.github/workflows/refresh-snapshot.yml` da versão anterior foram preservados.

O exportador exige `SUPABASE_URL` e `SUPABASE_SERVICE_ROLE_KEY` nos segredos do job. O nome da view é configurável com `SUPABASE_CHAT_VIEW`. Revise a view contra o esquema real do banco antes de executá-lo. **Nunca publique a service_role no GitHub Pages nem no frontend.**

### Opcional: continuar recuperando documentos do Vector Store OpenAI

Se os registros ainda estão em um vector store da OpenAI e você quer migrar primeiro **apenas a geração de texto**, configure também:

```dotenv
# Sem SNAPSHOT_URL, estes campos permitem usar o corpus vetorial antigo:
OPENAI_API_KEY=sk-...
OPENAI_VECTOR_STORE_ID=vs_...
RETRIEVAL_MODE=auto
```

O backend fará uma requisição HTTP à API OpenAI **somente para recuperar evidências** e enviará as evidências à Groq para redigir a resposta. Isso ainda pode gerar custos de armazenamento/consulta na OpenAI. Para independência completa, use o snapshot na CDN e deixe essas variáveis vazias. Quando se utiliza somente busca vetorial, o bot não afirma totais ou rankings globais.

## 4. Modelos e custo

Configure `GROQ_MODEL` para selecionar o modelo:

| Modelo Groq | Entrada/1M tokens | Saída/1M tokens | Uso sugerido |
| --- | ---: | ---: | --- |
| `openai/gpt-oss-20b` | US$ 0,075 | US$ 0,30 | **Padrão**, econômico e rápido |
| `openai/gpt-oss-120b` | US$ 0,15 | US$ 0,60 | Maior capacidade para respostas complexas |

Valores conforme documentação pública da Groq consultada em **16/11/2026**: <https://console.groq.com/docs/models>. O custo real depende de tokens de entrada, resposta, raciocínio, contexto e cache. Para um cenário ilustrativo de 2.500 tokens de entrada + 400 de saída por pergunta (incluindo raciocínio contabilizado na saída), seriam aproximadamente **US$ 0,31 / 1.000 perguntas** no 20B, **antes** de outros custos.

`GROQ_REASONING_EFFORT=low` minimiza esforço de raciocínio nos modelos GPT-OSS, com as opções `medium` e `high`. O raciocínio interno nunca é exibido no chat. Se trocar para um modelo diferente de GPT-OSS, o adaptador não envia `reasoning_effort` nem `include_reasoning`, evitando erros de parâmetros não suportados.

`MAX_OUTPUT_TOKENS` controla o teto de **tokens totais de conclusão** (texto + possíveis tokens internos de raciocínio). Se uma pergunta complexa for interrompida cedo, aumente esse valor e observe o custo. `MAX_EVIDENCE=6` e histórico de seis mensagens limitam o volume enviado ao modelo; `ENABLE_RESPONSE_CACHE=false` preserva privacidade por padrão. Perguntas estatísticas simples são respondidas diretamente pelo snapshot, sem uso de tokens.

**Não use** `llama-3.1-8b-instant` ou `llama-3.3-70b-versatile` como padrão em contas Free/Developer: foram descontinuados nesses planos em agosto/2026. Consulte <https://console.groq.com/docs/deprecations> e os modelos disponíveis no seu projeto.

## 5. Arquivos principais

- `llm.py`: instruções, geração por Groq e busca HTTP opcional no vector store antigo.
- `app.py`: endpoints Flask, validação, histórico, cache opcional, streaming SSE e controles básicos.
- `nuca_data.py`: cache do snapshot, busca lexical e cálculos estatísticos sem IA.
- `static/` + `templates/`: interface responsiva, streaming, referências, idiomas PT/EN.
- `scripts/export_snapshot.py`: exportação de uma view Supabase pública e aprovada.
- `.github/workflows/refresh-snapshot.yml`: agendamento da exportação.
- `tests/`: testes sem chaves reais e sem conexões externas.

## 6. Testes

```bash
python -m pytest -q tests/
python -m compileall -q app.py llm.py nuca_data.py
node --check static/js/chat.js
```

Sem uma chave `GROQ_API_KEY` real, os testes validam o protocolo de streaming com cliente simulado, mas **não confirmam uma chamada efetiva à Groq**. Também não é possível verificar as ações ou valores reais do Selo UNICEF sem configurar a base de produção.

## 7. Segurança e limites

- Nunca envie a chave Groq ao navegador. Apenas Flask deve conhecer `GROQ_API_KEY`.
- Há rate limit em memória por processo. Para produção pública, implemente limite distribuído na Cloudflare e cotas na Groq.
- Toda pergunta e evidência enviada ao modelo é processada pela Groq: revise políticas, adequação e privacidade dos textos.
- Estatísticas só são confiáveis se o snapshot for completo e atualizado; não confunda **pessoas mobilizadas** com adolescentes únicos.
- O Heroku/Gunicorn/proxy podem impor limites de tempo ao streaming. Ajuste limites conforme necessário.
